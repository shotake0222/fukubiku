# Straid 運用管理システム

Straid合同会社の2サービス（fukubiku / あてんど）のクライアント提供AR体験を、
1つの管理画面から運用するためのツールです。`/admin` にログインすると、サービス
選択画面からそれぞれの管理画面に入れます。

## サービス構成

| サービス | 管理画面 | オブジェクト管理 | クライアント提供URL | ドメイン |
| --- | --- | --- | --- | --- |
| fukubiku（福引AR） | `/admin/fukubiku/*` | `/admin/fukubiku/presets` | `/v/[hash]` | app.fukubikiu.com |
| あてんど（XRコンテンツ配信） | `/admin/attend/*` | `/admin/attend/presets` | `/a/[hash]` | app.attend-ar.com |

fukubikuとあてんどは全く別のサービスのため、ログイン（`/admin`でのサービス選択）以外の
画面はすべて分離しています。表示オブジェクトのテンプレートライブラリもサービスごとに
別ページ・別データで管理しており、一方のサービスで登録したオブジェクトがもう一方の
編集画面に紛れ込むことはありません（データ上は共通の`preset_objects`テーブルですが、
`service`列で厳密に絞り込んでいます）。

### fukubiku
- 注文情報の管理（クライアント名・注文日・納期・担当者・個数・延長確認日）
- 表示オブジェクト（3Dモデル/動画/GIF）の選択、またはアップロード
- 表示方式（A-Frame / MindAR）の選択
- MindAR選択時は、ターゲット画像をアップロードするとブラウザ上で自動的に `.mind` ファイルへコンパイル
- 注文ごとにハッシュ化されたクライアント提供URL（`/v/[hash]`）を自動発行
- 景品セット（当たり/外れ/1等/2等など）をまとめて一括作成する機能あり

### あてんど
- 案件（クライアント単位）と、その下に複数のアイテム（柄・グッズ単位）を管理
- 1アイテムに複数の「発火条件」を設定可能（例: 同じキーホルダーに画像トラッキングとGPSの両方を用意し、
  来訪者はどちらかを選んでAR体験を開始できる）
- 発火条件ごとにARモードを選択: A-Frame（マーカー）/ MindAR画像認識 / MindAR顔認識 / GPS位置トリガー
- 1つの発火条件に複数のARオブジェクトを配置可能（位置・大きさ・回転を個別に指定）
  例: コースター1枚から複数のキャラクターが同時に出現する、など
- プラン（ライト/スタンダード/エンタープライズ）の目安を表示（強制制限なし）
- NFCタグの発注枚数・使用済み枚数の進捗管理
- アイテムごとにハッシュ化されたクライアント提供URL（`/a/[hash]`）を自動発行
  （発火条件が複数ある場合、閲覧画面上部のタブで来訪者が切り替えられる）

## 技術スタック
- Next.js 14 (App Router) + TypeScript + Tailwind CSS
- Supabase（Postgres / Auth / Storage）
- Vercel（ホスティング、1つのデプロイに2つの独自ドメインを割り当て）
- A-Frame / AR.js（マーカー・GPS）/ MindAR（画像認識・顔認識）を、CDNまたは自前ホスティングでクライアントサイドに読み込み

## セットアップ手順

### 1. Supabase プロジェクト
1. Supabaseダッシュボード → 該当プロジェクトを開く
2. 「SQL Editor」で `supabase/schema.sql`（fukubiku）→ `supabase/schema_attend.sql`（あてんど）の順に貼り付けて実行
   - `orders` / `preset_objects` / `attend_projects` / `attend_experiences` テーブル、`assets` ストレージバケット、RLSポリシーが作成されます
3. 「Authentication → Users」で管理者用アカウントを作成（メール／パスワード）
   - このアカウントで管理画面 (`/admin`) にログインします（fukubiku・あてんど共通ログイン）
4. 「Project Settings → API」から以下を控える
   - Project URL
   - `anon` public key
   - `service_role` key（絶対に公開しないこと）

### 2. 環境変数
`.env.local.example` を `.env.local` にコピーして値を入力（ローカル開発用）。

```
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
SUPABASE_SERVICE_ROLE_KEY=...
NEXT_PUBLIC_SITE_URL=https://app.fukubikiu.com
NEXT_PUBLIC_ATTEND_SITE_URL=https://app.attend-ar.com
```

Vercelプロジェクト（fukubiku）の Settings → Environment Variables にも同じ値を登録してください。

### 3. ローカル動作確認
```
npm install
npm run dev
```
`http://localhost:3000/admin` にアクセスし、Supabaseで作成した管理者アカウントでログイン。

### 4. デプロイ
GitHubリポジトリへ push すると、Vercelが自動でビルド・デプロイします。

```
git add -A
git commit -m "feat: 管理画面・URL発行ツールを追加"
git push origin main
```

### 5. ドメイン設定（app.attend-ar.com を追加する場合）
このプロジェクトは1つのVercelデプロイで2つのドメインを提供します（パスで
サービスを判別しているため、どちらのドメインでアクセスしても同じアプリが動きます）。

1. Vercelダッシュボード → 対象プロジェクト → Settings → Domains
2. 「Add」で `app.attend-ar.com` を追加
3. Vercelが指示するDNSレコード（通常はCNAME → `cname.vercel-dns.com`、ルート直下なら
   ALIAS/Aレコード）を、attend-ar.com を管理しているDNS（Route53やお名前.comなど）に追加
4. DNS反映後、Vercel側で「Valid Configuration」になれば完了
5. 環境変数 `NEXT_PUBLIC_ATTEND_SITE_URL=https://app.attend-ar.com` をVercelにも設定して再デプロイ
   （あてんどの管理画面に表示されるクライアント提供URLがこのドメインで表示されるようになります）

`app.fukubikiu.com` 側は従来どおりで変更不要です。

### 6. 表示オブジェクト（プリセット）の登録
各サービスの管理画面（fukubikuは`/admin/fukubiku/presets`、あてんどは`/admin/attend/presets`）
から、動画(.mp4)/GIF/画像/`.glb`形式の3Dモデルとサムネイル画像を登録しておくと、
そのサービスの編集画面のプルダウンから選択できるようになります。

- **fukubiku**: カテゴリは「あみだくじ/ボックス抽選/ダーツ/ガラガラ抽選/おみくじ/スクラッチ」の
  固定リストから選択（+その他自由入力）。
- **あてんど**: 今後アクリルスタンド・キーホルダー・コースターなど扱う商材の幅が広がる想定のため、
  カテゴリは完全自由入力（過去入力からの候補サジェスト付き）。さらに、
  - 「個別案件」= 特定クライアント向けの単発カスタム施策
  - 「サービスメニュー」= 複数クライアントへ横展開する定型サービス施策
  の2分類を登録時に選び、一覧もこの分類→カテゴリの二階層で表示されます。fukubikuの
  カテゴリ（あみだくじ等）はあてんど側の画面には一切表示されません。

**fukubikuの既定テンプレート一式**: `supabase/seed_presets.sql`（各カテゴリの透過MP4）と
`supabase/seed_object_presets.sql`（各カテゴリの立体オブジェクト、`.glb`）をSupabase SQL Editorで
実行すると、6カテゴリ（あみだくじ/ボックス抽選/ダーツ/ガラガラ抽選/おみくじ/スクラッチ）分の
既定テンプレートが`preset_objects`に一括登録されます。立体オブジェクト版は、あみだくじ/ボックス抽選/
おみくじが「1等〜6等＋参加賞」、ダーツ/ガラガラ抽選/スクラッチが「当たり/大当たり/クーポン/はずれ/
参加賞」という各カテゴリの実際の賞グレードに合わせてメダル・ギフトボックス型のオブジェクトを割り当てています
（同じ賞グレードの意匠はカテゴリ間で共通のモデルを再利用しています。カテゴリごとに見た目を作り分けたい
場合は、該当行の`model_url`/`thumbnail_url`を差し替えるか、管理画面から個別に登録し直してください）。
アセット本体は`public/presets/<category>/`配下に`*_3d.glb`/`*_3d_thumb.png`として同梱済みです。
再実行しても壊れませんが、同名レコードが重複登録されるため、再登録したい場合は該当行を
`delete from preset_objects where name like '%（3Dオブジェクト）';`などで削除してから実行してください。

### 7. マーカー管理（あてんど）
`/admin/attend/markers` から、A-Frame(AR.js)のマーカーとMindARのイメージトラッキング用
画像を、案件（クライアント・企業）ごとに登録して一覧管理できます。

- **A-Frame(AR.js)マーカー**: [AR.js Marker Trainingツール](https://ar-js-org.github.io/AR.js/three.js/examples/marker-training/examples/generator.html)
  で画像から生成した`.patt`ファイルをアップロードします（任意でプレビュー用の画像も添付可能）。
  このツールでの`.patt`生成自体はAR.js公式の外部ツールで行う必要があります。
- **MindARターゲット画像（複数画像対応）**: 画像は1枚だけでなく**複数枚まとめて**アップロードできます。
  MindARのコンパイラは元々「複数画像を1つの`.mind`ファイルにまとめて同時トラッキングする」ことが
  標準の使い方になっており、本システムもこれをデフォルトの挙動として実装しています。
  アップロードした画像はそれぞれ`targetIndex`（0, 1, 2...）が自動採番され、1つの`.mind`ファイルへ
  コンパイルされます。マーカー詳細からは後日追加で画像を足すこともでき、その場合は既存の画像と
  合わせて自動的に再コンパイルされます（既存の`targetIndex`は維持されたまま、新しい画像が続きの
  番号で追加されます）。

登録したマーカーは、案件配下の各アイテムの発火条件編集画面（A-Frame / MindAR画像認識選択時）
のプルダウンから選んで使い回せます。案件をまたいで一覧できるので「どの企業にどのマーカーを
発行したか」を後から追いやすくなっています。

**複数画像マーカーとオブジェクトの紐付け**: MindAR画像認識の発火条件で、`targetIndex`が複数ある
マーカー（＝複数画像を登録したマーカー）を選択すると、「表示オブジェクト」の各行に
「対象画像（このオブジェクトを表示する画像）」という選択欄が追加で表示されます。
ここで特定の画像を選べば「この画像を認識したときだけこのオブジェクトを表示」、
未選択（「すべての画像で表示」）のままなら「登録したどの画像を認識してもこのオブジェクトを表示」
という挙動になります。これにより、例えば1つのキーホルダーの柄違い（複数デザイン）それぞれに
別々のARコンテンツを割り当てる、といった使い方が可能です。
公開ページ（`/a/[hash]`）側は、マーカーに登録された画像の数だけ同時に検出用のエンティティを
配置するため、来訪者はどの画像をカメラに映してもそれぞれ対応するARコンテンツが表示されます。

## 使い方の流れ（fukubiku）
1. 「新規注文」で注文情報を入力して保存
2. 遷移先の注文編集画面で「表示方式」（A-Frame / MindAR）を選択
3. 「表示オブジェクト」をプリセットから選ぶか、独自ファイルをアップロード
4. MindARを選んだ場合は、クライアント提供の画像をアップロード → 自動でコンパイルされ `.mind` ファイルが生成される
5. 「保存」を押すと、必要な情報が揃っていれば状態が「公開準備完了」になり、クライアント提供URL（`https://app.fukubikiu.com/v/xxxxxxxxxx`）が表示される
6. そのURLをクライアントに共有すればAR体験を閲覧可能

## 使い方の流れ（あてんど）
1. 「新規案件」でクライアント情報・プラン・NFCタグ発注枚数を入力して保存
2. 案件編集画面で「+ アイテムを追加」して柄・グッズごとのアイテムを作成
3. アイテム編集画面で「+ 発火条件を追加」し、ARモード（A-Frame / MindAR画像認識 / MindAR顔認識 / GPS）を
   選択して、モードに応じたマーカー画像・ターゲット画像・顔アンカー・GPS座標を設定して保存
   （1アイテムに発火条件はいくつでも追加可能。例: 同じキーホルダーに「画像トラッキング」と
   「GPS」の両方を用意し、来訪者はどちらかを選んでAR体験を開始できる）
4. 各発火条件の「+ オブジェクトを追加」で表示オブジェクトを追加（プリセットから選ぶか独自ファイルをアップロード）。
   1つの発火条件に複数オブジェクトを配置し、位置・大きさ・回転を個別に調整できる。
   MindAR画像認識で複数画像マーカーを使う場合は、オブジェクトごとに「対象画像」を指定して
   どの画像を認識したときにそのオブジェクトを表示するか選べる（詳細は上記「7. マーカー管理」参照）
5. **クライアント提供URL**（`https://app.attend-ar.com/a/xxxxxxxxxx`）はアイテム編集画面の**一番上**に
   常時表示されており、いつでもそこからコピーできる。アイテムの状態を「公開準備完了」に切り替えると
   実際にAR体験が閲覧可能になる（未切り替えの間はURLへアクセスしても準備中の表示になる）
6. 案件編集画面でNFCタグの使用済み枚数を随時更新して進捗管理
